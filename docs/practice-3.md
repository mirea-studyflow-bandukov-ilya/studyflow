## Чем GitHub покрывает Azure Delivery Plans

| Требование | Реализация |
|---|---|
| Установка Delivery Plans | Используется встроенный GitHub Projects Roadmap; расширение Azure не устанавливается |
| Общий план нескольких команд | Один Roadmap, группировка Delivery team, разные поля итераций |
| Создание историй и изменение расписания | Настоящие GitHub Issues #179/#180, поля Project и даты issue fields |
| Зависимость | Связь карточек GitHub: #31 зависит от #180 |
| Маркер значимой даты | Нативная веха GitHub; точный пурпурный цвет и раскрытие подписи на странице календаря |
| Масштаб и сворачивание | Нативный Roadmap и календарь документации |
| Поля / только заголовки, клавиша T | На странице календаря; в GitHub доступны таблица полей и настройка Show date fields |

Календарь документации использует [проверенные данные](https://mirea-studyflow-bandukov-ilya.github.io/Docs/data/practice-3.json), выгруженные из видимой таблицы GitHub до и после переносов. Это снимок на 11.11.2026, а не подключение к частному Project. Выбор сценария, масштаба, Done и сворачивание сохраняются только в браузере. Кнопка «Сбросить вид» возвращает согласованный план. Повторная загрузка страницы сохраняет выбранный вид. Перед показом после новых изменений Project снимок нужно обновить.

## Короткий показ и ответы

1. Открыть календарь GitHub: показать две команды, разные даты итераций и отсутствие #32.
2. В календаре выбрать исходный план и объяснить, почему #31 нельзя надёжно планировать раньше #180.
3. Выбрать согласованный план; показать три переноса и запас в 9 дней. В #31 открыть раздел связей.
4. Нажать маркер отпуска; приблизить и отдалить календарь; переключить показ завершённых карточек и нажать T; свернуть и раскрыть команду.
5. Открыть таблицу GitHub и проверить поля #31, #179, #180. Объяснить различие «конфликт сроков устранён» и «зависимость выполнена».

План поставки согласует работу автономных групп на общем календаре. Итерации команд могут не совпадать. Зависимость связывает результат поставщика с началом работы потребителя; раннее обнаружение конфликта позволяет изменить приоритеты до срыва сроков. Маркер — контрольная дата, а не задача. Скрытие завершённых карточек меняет представление, не удаляя выполненные элементы.
