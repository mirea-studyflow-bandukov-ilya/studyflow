## Задача 1. Создание и редактирование Wiki

Существующая Wiki, созданная в практике 1.1, дополнена страницами:

- Домашняя: основной файл Home.md сохранён, название содержимого изменено на «Домашняя», добавлено приветствие.
- Начало работы: создана страница с сообщением «Добавлена заглушка для начала работы».
- Окружение для разработки системы: создан нумерованный Markdown-список Windows Server 2016, Team Foundation Server 2018, Visual Studio 2019.

В отдельной редакции Team Foundation Server 2018 заменён на Azure DevOps. История страницы содержит обе версии. В веб-интерфейсе открыто сравнение: видны удалённая строка TFS и добавленная Azure DevOps. Кнопка Revert changes доступна; откат не выполнялся, поскольку в задании предлагается ознакомиться с возможностью отката.

Первоначально навигация содержала иерархию Домашняя → Начало работы → Окружение. Затем «Начало работы» поднята на один уровень с Домашней, а страница окружения осталась вложенной. На GitHub это представлено вложенными ссылками в _Sidebar.md. Перемещение иерархии сохранено отдельной редакцией; ссылки на страницы сохранились.

Проверен фильтр страниц по «нач». Полнотекстовый поиск GitHub по запросу repo:mirea-studyflow-bandukov-ilya/studyflow Azure вернул страницу окружения.

В настройках studyflow включена Wiki и установлен параметр Restrict editing to users in teams with push access only. Публичную Wiki могут читать все. Редактирование ограничено правами записи; расширять доступ на всех пользователей не требовалось.

Учебный список старых продуктов сохранён для упражнения из методички. Реальная среда нашего проекта отдельно описана на той же странице: GitHub, Git и веб-браузер; установки Windows Server или Visual Studio для этой практики не требуются.

## Задача 2. Документация из репозитория

Создан отдельный публичный репозиторий Docs с README. Файл README.md переименован в Our-team.md отдельным коммитом, затем наполнен описанием участника и порядка работы. Доступны Markdown-таблица, нумерованный список, выделение, ссылки и блок команды Git.

GitHub Pages публикует корень ветки main. Страницы Markdown обрабатываются Jekyll. Отдельно проверено, что Our-team.md отображается как страница сайта «Наша команда».

Название опубликованного раздела — «Документация». Исходные файлы, изменения и версии остаются в Docs. Новые коммиты в выбранной ветке запускают обновление Pages. Выбор другой ветки в настройках позволяет сменить публикуемую версию; одновременно в этой работе используется main.

## Задача 3. События и порядок страниц

В Docs создана папка Предстоящие-события. В неё отдельными коммитами добавлены События-Января.md и События-Февраля.md. Даты 2027 года на этих страницах явно обозначены как учебные примеры, а не реальное расписание занятий.

До задания порядка на опубликованном сайте зафиксировано алфавитное расположение: февраль перед январём.

Файл Предстоящие-события/.order содержит по одному имени страницы без расширения на строку:

```text
События-Января
События-Февраля
```

GitHub Pages сам по себе не интерпретирует формат .order Azure DevOps. Для сохранения смысла упражнения при сборке Jekyll файл events-order.json читает .order через include_relative. Навигация использует полученный порядок для бокового списка и списка событий на главной. Порядок задан в .order один раз и не дублируется вручную в нескольких списках.

Финальная проверка выполнена: [сборка и публикация завершились успешно](https://github.com/mirea-studyflow-bandukov-ilya/Docs/actions/runs/42888557288). На опубликованной главной странице оба списка показывают «События Января» перед «События Февраля» и получают порядок из .order. По ссылкам открыты обе страницы событий; таблицы дат и содержимое отображаются корректно.

## Сопоставление платформ

| Azure DevOps | Выполнение на GitHub |
| --- | --- |
| Project Wiki | Wiki репозитория studyflow |
| Домашняя страница | Home.md с заголовком «Домашняя» |
| Дочерние страницы и перенос в дереве | Вложенные ссылки _Sidebar.md и отдельные редакции навигации |
| Save with revision message | Сообщения Git-коммитов при сохранении Wiki |
| View revisions / compare / revert | History, Compare revisions и доступная кнопка Revert changes |
| Wiki security | Настройки Wiki и права записи репозитория |
| Publish code as wiki из Docs | Согласованная публикация Markdown из Docs через GitHub Pages |
| Выбор ветки и корневой папки публикации | Pages: main, / (root) |
| Автоматическое обновление после правок | Сборка и публикация Pages после коммитов |
| Порядок из .order | Чтение .order при сборке и применение порядка в навигации |

GitHub Pages — согласованная функциональная замена публикации кода как Wiki. Это отдельный сайт документации, а не вторая Wiki, появляющаяся внутри вкладки Wiki репозитория studyflow. Дерево Wiki GitHub представлено навигацией, а не деревом страниц Azure с перетаскиванием.
